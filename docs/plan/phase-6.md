# Phase 6: Security hardening

> **ID key:** **P** = Phase, **M** = Milestone. `P6-M2` = Phase 6, Milestone 2 · `P6-05` = Phase 6, task 05.

> **Status: draft.** Written ahead of time. Review and adjust it at the end of Phase 5, before starting.

**Goal:** defense in depth, with every layer proven by a test that **tries to break it**. The cluster only admits signed, compliant images. Pods can only reach what they're allowed to. Suspicious runtime behaviour alerts within a minute. Security posture is measured over time.

**Exit criteria:**

- [ ] An **unsigned** image, or one from outside our ECR, is rejected by the cluster in `ledgerpay-*` namespaces
- [ ] A privileged pod, a pod without limits and a `latest`-tagged image are each rejected
- [ ] With default-deny NetworkPolicies, a pod can't reach anything not on the allow-list, even with Istio removed from the path
- [ ] Unexpected egress (e.g. to a random internet host) is blocked by the mesh
- [ ] `kubectl exec` into a container fires a Falco alert in Slack in < 1 minute
- [ ] A Kubescape baseline score is recorded and improved, with remaining findings justified
- [ ] A threat model is written and each threat is mapped to a control

## P6-M1 Admission control

### P6-01: Kyverno + baseline policies
- **Scope:**
  - Kyverno via Argo CD (single replica in dev, HA toggle for prod)
  - Policies: disallow privileged / host namespaces / `hostPath`; require requests and limits; disallow the `latest` tag; restrict registries (`ledgerpay-*`: our ECR only; platform namespaces: an allow-list of upstream registries, with an ECR pull-through cache documented as the prod option); require probes in `ledgerpay-*`
  - Every policy starts in **Audit** and moves to **Enforce** once its policy reports are clean
- **Acceptance criteria:**
  - [ ] Policy reports are clean for all running workloads
  - [ ] In Enforce, each policy rejects a matching bad manifest (tests kept in `policy/kyverno-tests/` and run in CI with the Kyverno CLI)
- **Depends on:** Phase 3
- **Output:** `gitops/platform/kyverno/`, `policy/kyverno-tests/`

### P6-02: Image signature verification
- **Why:** closes the supply chain. Only images signed by **our** CI workflow can run.
- **Scope:**
  - Kyverno `verifyImages` for `ledgerpay-*`: Cosign keyless with issuer `token.actions.githubusercontent.com` and subject = this repo's `service-ci` workflow on `main`
  - Require an SBOM attestation
  - Mutate tags to digests
- **Acceptance criteria:**
  - [ ] An image pushed to ECR **without** a signature is rejected
  - [ ] An image signed by a different workflow is rejected
  - [ ] A normal release passes
- **Depends on:** P6-01
- **Output:** `gitops/platform/kyverno/`

### P6-03: Pod Security Standards everywhere
- **Scope:** `restricted` enforced on all `ledgerpay-*` namespaces (already done in Phase 3); `baseline` or `restricted` on platform namespaces wherever add-ons allow it; documented exceptions (e.g. Falco needs privileges)
- **Acceptance criteria:**
  - [ ] Every namespace has an explicit PSS level, and every exception has a written reason
- **Depends on:** P6-01
- **Output:** `gitops/platform/namespaces/`, `docs/security/pss-exceptions.md`

## P6-M2 Network isolation

### P6-04: Default-deny NetworkPolicies
- **Scope:**
  - Enforced by VPC CNI native network policies (enabled in Phase 2), so no extra CNI
  - Default deny for ingress and egress in every `ledgerpay-*` namespace
  - Allow rules generated by the library chart from the same call-matrix values that drive the AuthorizationPolicies (one source of truth)
  - DNS egress, istiod, Prometheus scraping, and RDS/Redis CIDRs allowed explicitly
- **Acceptance criteria:**
  - [ ] Test pods prove allowed and denied paths **at the network layer**, with Istio bypassed
- **Depends on:** Phase 4 AuthZ
- **Output:** `charts/ledgerpay-lib/`, `gitops/apps/*/`

### P6-05: Egress control
- **Scope:**
  - Istio `outboundTrafficPolicy: REGISTRY_ONLY`
  - `ServiceEntry`s only for Auth0 (JWKS), AWS APIs (SQS, STS, Secrets Manager) and the bank mock's virtual endpoint
- **Acceptance criteria:**
  - [ ] `curl https://example.com` from a service pod fails
  - [ ] Auth0 JWKS fetch still works
- **Depends on:** P6-04
- **Output:** `gitops/platform/istio/`

## P6-M3 Runtime and posture

### P6-06: Falco + Falcosidekick
- **Scope:**
  - Falco (modern eBPF) via Argo CD; Falcosidekick → Slack
  - Custom rules: shell in a container, unexpected outbound connection from `ledgerpay-*`, writes below `/etc`, read of service-account tokens by unexpected processes
  - Noise tuning documented
- **Acceptance criteria:**
  - [ ] `kubectl exec ... sh` produces a Slack alert in < 1 minute
  - [ ] No false positives during a 30-minute k6 run
- **Depends on:** Phase 5 (Slack routing)
- **Output:** `gitops/platform/falco/`

### P6-07: Kubescape posture tracking
- **Scope:**
  - Kubescape CIS/NSA scans: in GitOps CI (rendered manifests) and as an in-cluster scheduled scan
  - Score exported as metrics, with a Grafana panel for the trend
- **Acceptance criteria:**
  - [ ] Baseline score recorded; the top findings either fixed or justified in `docs/security/`
- **Depends on:** Phase 5
- **Output:** `.github/workflows/gitops-ci.yml`, `gitops/platform/kubescape/`, `docs/security/`

### P6-08: IAM least-privilege review
- **Scope:**
  - Review every role (CI roles, Pod Identity roles, cost-reaper role)
  - Tighten wildcard actions/resources; Checkov IAM checks enforced
  - Document each role's purpose and trust in `docs/security/iam-roles.md`
- **Acceptance criteria:**
  - [ ] No `*:*`; every wildcard has a written justification
- **Depends on:** —
- **Output:** `infra/`, `docs/security/iam-roles.md`

### P6-09: Secrets lifecycle
- **Scope:**
  - Rotation for the RDS master and per-service DB passwords (Secrets Manager rotation), proven to reach pods through ESO without downtime
  - Rotation runbook for the Auth0 Terraform client secret
- **Acceptance criteria:**
  - [ ] Rotating the wallet DB password during a k6 run causes no failed requests
- **Depends on:** Phase 3 ESO
- **Output:** `infra/`, `docs/runbooks/secret-rotation.md`
